## 三、本轮新发现：`test_data` 隔离是单向的 🔴

**现象**：普通写入（不带 `test_data`）可以合并进一个 `test_data` 桶。合并后该桶仍带 `provenance.kind=test`，于是可以被 `hard_delete` **物理删除** —— 落在里面的真实记忆跟着一起永久抹除。

**实证**（本轮实际发生）：

```
hold("今天下午把报税材料交给了会计…", test_data=True)  → 新建 76ec0bb08eb7（test 桶）
hold("今天下午把报税材料交给了会计…")                  → 合并→76ec0bb08eb7   ← 普通写入进了 test 桶
trace(76ec0bb08eb7, hard_delete=True)                  → 「已永久删除测试桶」 ← 连普通写入一起没了
```

**根因**：`src/tools/_common.py:817` 的合并分支条件

```python
if (not test_data and existing and existing[0].get("score", 0) > merge_threshold):
```

`not test_data` 只判断**这次写入**是不是测试数据，不判断**合并目标桶**是不是 test 桶。方向反了一半。

**为什么严重**：这是 `rule.md` §1「记忆永不被物理抹除」的直接绕过路径，而且完全静默 —— 用户看到的只是一次正常的「合并→」。

**触发条件（区分两条路径，别高估频率）**：
- **逐字相同的正文**：走 `find_exact_content` → `score=inf` → 跳过 `judge_same_event`，**无条件合并**。上面实证走的就是这条，门槛为零。
- **语义相近但措辞不同**：还要过检索分 > 75 *且* `judge_same_event` 置信度 ≥ 0.85（`_common.py:856`）两道关。这条路径本轮**未实测**，频率未知。

结论不依赖频率 —— 只要第一条路径存在，红线就已经被绕过了。

**建议**：在合并候选检查里加一条 —— 目标桶 `provenance.kind == "test"` 时直接 `break` 新建，与现有的 pinned / protected / `i_stage=candidate` 拦截放在同一处（`_common.py:833-841`）。这样测试桶只能由测试写入进入，`hard_delete` 的前提才真正成立。

## 四、观察项（非 bug，供你权衡）

1. **「服务器备份每天凌晨 3 点执行」→ domain=「硬件」**。定时任务/备份策略归到「硬件」不太贴切，「网络」或「事务」更准。R5 给的是「网络,事务」。单一 domain 时的选择偏窄。
2. **「喜欢咖啡」→ domain 含「情绪」**。prompt 举的例子是「开心/难过/愤怒/失落/兴奋」，「喜欢」是偏好陈述而非情绪表达，触发略宽。如果在意，可在规则里把「偏好/评价类表述不算情绪」写明。
3. **温和正面的日常被压成中性**（这一条不只是观感）：「周六跑五公里 + 燕麦粥」valence=0.50（R5 是 0.8），五领域日常也是 0.50，与「服务器备份」这种纯配置记录完全同分。而 `calc_emotion_score`（`ombrebrain/retrieval/bucket_scoring.py:102-103`）正是拿存储的 valence 算情感共鸣子分 —— 大量普通记忆挤在 0.50 上时，这个子分对它们就不再有区分度，是**检索侧的实际影响**，不只是显示偏好。中性事实的偏正修好了，代价落在这里。若要区分，可加一条「事件本身是愉快经历但无情绪词时给 0.6~0.7」。
4. **grow 39 字仍走 digest**：分流阈值仍是 30 字。正文不再捏造，但开头「回归测试短路径条目：」被抽成标题、正文只保留剩余部分，不是逐字。属 digest 的设计内行为，只是与 hold 的「逐字保存」直觉不同 —— 若希望 30~50 字也逐字，需要把分流阈值提到 50。
5. **五领域内容仍只保留 3 个具体 domain**（财务、家庭未进）。prompt 明确写的是「1~3 个 + 情绪额外」，属设计上限而非缺陷。

## 结论

R4 和 R5 提出的问题除 `extra_tags` 语义外全部解决，包括五轮换模型都没解决的四项打标问题 —— 从 prompt + 代码硬闸门两侧同时约束是对的路子，光靠 prompt 或光靠换模型都不行。本地测试套件也从 6 failed 回到全绿。

处理顺序建议：

1. **`test_data` 单向隔离**（第三节）—— 记忆不可物理抹除这条红线上的静默绕过路径，优先级最高
2. **valence 扁平化对检索的影响**（第四节 3）—— 有实际检索后果，不是观感问题
3. `extra_tags` 覆盖语义（第二节表格末行）—— 唯一还没动的 R4 遗留项
4. 第四节其余观察项 —— 都属可接受范围，按需处理
