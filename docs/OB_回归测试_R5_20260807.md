## 三、本轮新发现

### 3. `grow` 会改写正文，甚至补进原文没有的句子 🔴 最高优先级

输入（39 字）：
> 回归测试短路径条目：这段内容不到三十字，应该走 hold 单条快速路径而不被拆分。

落库（65 字）：
> 这是一条回归测试短路径条目，原文内容不到三十字，预期应走 hold 单条快速路径，**并保持为一个独立条目，不应继续拆分或扩展成多个记忆条目。**

加粗部分原文里根本没有 —— 模型自己补的。

路径已确认（不是推测）：`src/tools/grow/__init__.py:52` 按 `len(content.strip()) < 30` 分流，39 字 ≥ 30 → 走 `core` → `dehydrator.digest()`；返回格式 `1条|新1合0 batch:...` 也是 core 的，不是 shortpath 的「短内容已按 hold 路径保存为单条记忆」。根因是 `DIGEST_PROMPT` 规则 6「单个条目内容不少于 50 字，过短的零碎信息合并到最相关的条目中」（`src/dehydrator.py:183`）—— 低于 50 字的输入被逼着扩写凑数。

而 `grow` 的工具说明写的是「短内容(<30 字)走 hold 单条快速路径，不强行拆分」—— **30~50 字这一段正好掉进「必须扩写到 50 字」的区间**，既不走快速路径，又会被改写。对一个记忆系统来说这是捏造记忆，比丢标签严重得多。

**建议**：把规则 6 从「不少于 50 字」改成「不足 50 字的条目原样保留，禁止为凑长度补充原文没有的信息」；或者把 hold 快速路径的阈值从 30 字提到 50 字，让这段区间不进 digest。

### 4. `breath_advanced` 的 domain / valence / arousal 过滤在无 query 时被静默忽略 🔴

实测：
- `breath_advanced(domain="情绪", max_results=5)` → 返回 5 条，**没有一条 domain 含「情绪」**，而库里唯一真正带「情绪」的桶反而没返回。
- `breath_advanced(domain="情绪", importance_min=1, max_results=5)` → 返回 **19 条全部记忆**，domain 和 max_results 双双失效。

根因（`src/tools/breath/__init__.py:129-155`）：`domain` / `valence` / `arousal` 只传给了 `surface_search`（有 query 分支）。另外两个分支的函数签名里压根没有这几个参数：
- `surface_default(max_results, max_tokens, tag_filter)`（`breath/surface.py:64`）
- `surface_by_importance(importance_min, max_tokens, tag_filter)`（`breath/importance.py:113`）—— 连 `max_results` 都不接

而工具描述写的是「domain 逗号分隔, valence/arousal 0~1(-1 忽略)」，没有任何「仅检索模式生效」的限定。按文档传参会拿到一份看起来正常、其实没过滤的结果 —— 最坏的失败方式。

**建议**：要么把三个参数透传进这两个分支，要么在参数被忽略时明确返回提示；工具描述同步写清适用范围。

### 5. `test_data=True` 不隔离 plan 自动闭环 🟡

`store_core` 无条件 fire `check_plan_resolution`，`test_data` 不参与判断。测试写入仍会被拿去判定**真实**的 active plan。本轮因为有了证据校验，实测没有误伤，但隔离语义上仍不完整 —— 测试数据不该有能力关掉真实承诺。

**建议**：`test_data=True` 时跳过 `check_plan_resolution` 与 `check_duplicate_for`。
